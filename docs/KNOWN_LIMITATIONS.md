# Known limitations

Maintained throughout v0.1. Entries are added when a limitation is discovered or accepted; each notes the milestone that introduced it.

- **Verification environment (M0):** Playwright WebKit is desktop WebKit with mobile emulation, not iOS. Standalone mode, Home Screen storage, the real keyboard, safe areas and the status bar can only be verified by a human on a device. See `docs/IOS_VERIFICATION.md` (created in M11).
- **Splash screen device list (M1):** the iPhone sizes in `scripts/brand/devices.ts` were not verified against Apple's current specifications. A device with no matching image shows a plain background-colour launch screen instead.
- **Theme/text-size storage (M1):** until M2 they live in localStorage only (cleared with site data).
- **Japanese ambiguity (M8)** IPADIC gives one contextual reading. Rare names, pronunciation across lines, and choices such as `kun` versus `kimi` can differ from the intended lyric. The engine flags known ambiguities and uses exact JMdict fallbacks for unreadable forms. Poetic readings such as 運命 as `さだめ` need pasted ruby. Mixed kanji/kana with irregular alignment can receive one reading over the whole token.
- **Korean (M4):** pronunciation rules are deterministic but ㄴ-insertion and a few Sino-Korean ㄹ cases come only from a small exceptions table (`engine/ko/exceptions.ts`); verbs are lemmatised heuristically (the 20.8 MB ko-dic was rejected on size).
- **Mandarin (M7)** Traditional text uses an OpenCC shadow for readings. Context-sensitive 得 and 地 can still be misread, and neutral-tone choices can differ between dictionaries. Erhua uses a separate character reading, with contextual suffix detection and uncertainty flagging still incomplete. The fixture suite passes the accuracy gate, with differences listed in `docs/LINGUISTIC_REPORT.md`.
- **Linguistic fixtures (M4):** all fixtures are self-authored by the implementing agent and unreviewed by a fluent speaker; the own Korean module's 100 % on its starter set is circular.
- **Dictionaries (M4):** the CC BY-SA family requires attribution and ShareAlike for the distributed packs. The About & licences screen (M9) states Wiktionary as CC BY-SA 4.0 and GFDL per kaikki.org; the exact wording on Wiktionary's own reuse page was not re-fetched, so it is worth a manual check before wide public release.
- **Korean romanisation (M5):** Hanja (e.g. 愛) and Japanese inside a Korean song stay unannotated and show a `?` in Learn mode. ㄴ-insertion and Sino-Korean ㄹ exceptions beyond the 11-word table are not predicted. Jamo-only text (ㅋㅋ) is transliterated letter by letter with low confidence.
- **Language packs (M8)** Japanese, Mandarin and Cantonese need a one-time download. Songs retain original text and progress if a pack is missing. Interrupted installations can restart using a cached download, with no partial byte resume. A fresh pack build requires the exact source archives in `.cache/dicts` or from their publishers. The live CC-CEDICT URL changes over time, so a missing pinned archive can block a fresh build until the pin is deliberately refreshed.
- **Japanese resources (M8)** The generated readings need a module worker. If it fails, the app shows the original and any pasted readings. If the browser clears Cache Storage independently of IndexedDB, removing and redownloading the pack restores the tokenizer. Native iOS memory and Home Screen behaviour remain unverified.
- **Offline shell (M8)** The precache is 2.264 MiB. The worker and main-thread fallback carry separate Chinese reader chunks, and the shell includes the Japanese loader for cold offline analysis. See ADRs 0010 and 0011. Playwright covers installed-pack offline workflows. Real iOS Home Screen behaviour and update prompts remain unverified.
- **Learn mode (M6):** the long-press line menu (copy original/romanised) is not implemented.
- **Word sheet (M9):** the Korean dictionary is optional (2.1 MB). Lemmatisation is heuristic plus irregular-form candidates; names, slang and rare compounds are often missing, and ㄹ-dropping verbs (분다) are not matched. Korean definitions come from Wiktionary and kengdic (kengdic glosses are terse and sometimes noisy). Cantonese meanings come from CC-Canto, falling back to CC-CEDICT only if the Mandarin pack is installed. English words, Hanja and unreadable segments are not tappable. Meaning relevance was measured on a 20-word self-authored probe only.
- **Karaoke syllables (UX checkpoint):** syllable separation exists for Korean only. Mandarin/Cantonese are already per syllable; Japanese mora splitting was deliberately not implemented (see ADR 0012).
- **Corrections (M10):** structural corrections are limited to split, merge, "English" and "Do not annotate"; re-analysing a span as another language and the line menu's "Set line language" are not implemented (ADR 0013). Splitting a Japanese word keeps readings only where furigana units line up with the cut. Corrections do not change the romanised text used by Library search. The "typed reading must have one syllable per character" rule means irregular readings of Chinese words must be entered per character.
- **Lyrics search (M12):** LRCLIB is community data with no stated licence and no uptime guarantee; anonymous use is rate-limited (the app waits out `Retry-After`). Only plain lyrics are shown; synced lyrics are stored for the future but not displayed. Search is by title/artist only. The live-service test is opt-in, so CI cannot detect a provider-side API change.
- **Romanised import (issue #4):** only Korean and Japanese (kana, no kanji) can be reconstructed; Mandarin and Cantonese romanisation is not supported. Korean spellings are candidates (original spelling among them for ~59 % of words, first for ~29 % on self-authored fixtures). The pasted romanisation is restorable only until the song is saved. See ADR 0016.
