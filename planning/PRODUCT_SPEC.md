# Overtone — Product Specification (v0.1)

> The product name is **Overtone** (see [DESIGN_SYSTEM.md §1](DESIGN_SYSTEM.md#1-name-and-brand)). It was previously called `romanised-learner`.

Requirement keywords: **MUST** = required for v0.1 completion. **SHOULD** = expected unless documented as infeasible with a defensible alternative. **MAY** = optional, only if cheap and non-disruptive. **OUT** = explicitly not in v0.1.

---

## 1. Product vision

Overtone is a local-first, account-free lyrics-learning app for Korean, Japanese, Mandarin and Cantonese songs (with English segments inside them). A learner pastes lyrics, and Overtone shows the original text with pronunciation above it, lets them tap words for meanings, track which lines they know, and switch to a large romanised karaoke view or a clean reading view.

It is used primarily as an installed iOS Home Screen web app, and it must feel like a carefully made independent music app, not a website.

### 1.1 Principles

1. **The library is sacred.** Nothing the user enters is ever silently lost. Storage is assumed to be evictable; backups are first-class.
2. **Local-first, account-free.** Every installation has its own independent IndexedDB database. No accounts, no server-side user storage, no authentication, no sync. All processing happens on the device. The only network calls are: loading app/resource files from the app's own origin, and the optional, user-initiated lyrics search.
3. **Honest linguistics.** Readings are generated by named, deterministic or statistical tools whose limits are documented. Uncertain output is marked as uncertain. Users can correct anything, and corrections stick.
4. **One source of truth.** Learn, Karaoke and Clean modes are three views of the same processed data.
5. **Free to run.** Static hosting only. No paid APIs, no hosted inference.

### 1.2 Target user

A self-motivated learner (often a fan of K-pop, J-pop/anime, C-pop or Cantopop) who wants to sing along accurately and gradually understand what they are singing. They may only be able to read some scripts. They use an iPhone most of the time, often offline (commuting, travelling).

### 1.3 Non-goals for v0.1 (OUT)

- Audio playback, YouTube embeds, timed or synchronised lyrics, auto-scroll.
- Spaced repetition, vocabulary decks, statistics dashboards, streaks, gamification.
- Accounts, cloud sync, sharing between users, collaborative libraries.
- Machine translation of whole lines (no free, offline, legally clean option of acceptable quality; see LANGUAGE_ENGINE.md §10).
- Native app store builds.

The architecture leaves room for these (ARCHITECTURE.md §12) without building infrastructure for them.

## 2. Supported languages

| Language | Script(s) | Pronunciation output | Meanings |
|---|---|---|---|
| Korean | Hangul (Hanja rare) | Revised Romanization, pronunciation-based, by word | English glosses per word (lemma lookup) |
| Japanese | Kanji, hiragana, katakana | Hiragana furigana over kanji + Modified Hepburn romaji per word | English glosses per word (JMdict) |
| Mandarin | Simplified or Traditional Han | Hanyu Pinyin with tone marks, per character | English glosses per word (CC-CEDICT) |
| Cantonese | Traditional (or Simplified) Han, Cantonese-specific characters | Jyutping with tone numbers, per character | English glosses per word (CC-Canto + CC-CEDICT) |
| English | Latin | None — shown as-is | None in v0.1 |

Mandarin and Cantonese share a script. The song's selected language decides which reading system applies to Han characters; Overtone never claims to tell them apart reliably by script alone.

## 3. Information architecture

```
Library (home)
 ├─ Search · language filter · sort
 ├─ Song row → Song screen
 └─ Add Song (sheet) ─┬─ Manual entry (default)
                      └─ Search online (LRCLIB) → pick result → prefilled manual entry
Song screen
 ├─ Mode switcher: Learn | Karaoke | Clean
 ├─ Learn: annotated lines, tap word → Word sheet, tap line check → learned
 ├─ Karaoke: romanised only, large
 ├─ Clean: original ⇄ romanised toggle
 └─ ⋯ menu: Edit lyrics · Edit details · Re-process · Reset progress · Delete
Word sheet (Learn only): reading, romanisation, meanings, source, "Correct…"
Correction sheet: edit reading / romanisation / meaning / language / word split
Settings
 ├─ Appearance (System / Light / Dark), text size
 ├─ Romanisation preferences (per language)
 ├─ Offline language data (status, size, download, remove)
 ├─ Backup: Export, Import, last backup time, storage status
 └─ About & licences (data sources and attributions)
```

Three top-level destinations only: **Library**, **Song**, **Settings**. No tab bar in v0.1 (Settings is reached from the Library header); this keeps the lyric screen free of chrome.

## 4. User journeys and acceptance criteria

Each journey lists acceptance criteria (AC). Every MUST criterion maps to at least one automated test in TEST_STRATEGY.md, or to the manual iOS checklist where automation cannot reach.

### J1 — First launch

1. User opens Overtone (browser or Home Screen).
2. Library shows an empty state: brand mark, one-sentence explanation, a primary **Add a song** button, and a secondary hint about adding to the Home Screen when not running standalone on iOS.

AC:
- J1.1 MUST: Empty state renders without network once the app has been loaded once.
- J1.2 MUST: The Add Song action is reachable with one tap and by keyboard.
- J1.3 SHOULD: When running in iOS Safari (not standalone), a dismissible "Add to Home Screen for offline use and safer storage" tip appears once. It is never shown in standalone mode.

### J2 — Add a song manually (default path)

1. Tap **Add a song** → a full-height sheet opens on the **Paste lyrics** tab.
2. Fields: Title (required), Artist (optional), Language (Auto-detect · Korean · Japanese · Mandarin · Cantonese; default Auto-detect), Lyrics (multiline, required).
3. While typing lyrics with Auto-detect, a small inline hint shows the detected language ("Looks like Japanese") with a confidence state. For Han-only text it says "Chinese — choose Mandarin or Cantonese" and does not guess silently.
4. Tap **Save**. The song is stored immediately (raw text first), the sheet closes, and the Song screen opens showing the lyrics with a processing indicator. Annotations fill in progressively.

AC:
- J2.1 MUST: Original text is stored byte-for-byte after Unicode NFC normalisation and line-ending normalisation (`\r\n`/`\r` → `\n`). Blank lines, punctuation, full-width characters, section labels (e.g. `[Chorus]`, `(Repeat)`) and leading/trailing spaces within lines are preserved for display.
- J2.2 MUST: Save is disabled until Title and Lyrics are non-empty; validation messages are announced to assistive tech.
- J2.3 MUST: If Language is Auto-detect and the text is Han-only (no kana/Hangul), Save requires the user to choose Mandarin or Cantonese (the detector may pre-select its guess, clearly labelled as a guess).
- J2.4 MUST: Saving never waits on language processing. A crash or failure in processing never loses the saved song.
- J2.5 MUST: Input limits: title ≤ 200 chars, artist ≤ 200 chars, lyrics ≤ 20,000 chars and ≤ 1,000 lines. Exceeding them shows a clear message (not silent truncation).
- J2.6 MUST: Draft content in the Add sheet survives accidental dismissal (swipe down / Escape): the sheet asks "Discard this song?" if fields are non-empty. The draft is also autosaved to IndexedDB so an app kill doesn't lose a long paste.
- J2.7 MUST: The keyboard never covers the focused field or the Save button on iOS.
- J2.8 SHOULD: Pasting lyrics that contain Aozora-style ruby (`|運命《さだめ》` or `運命《さだめ》`) is recognised for Japanese: the bracketed reading becomes a user-supplied reading and the brackets are removed from display text. A toggle "Use readings from pasted text" (default on when detected) controls this.

### J3 — Search lyrics online (optional path)

1. In the Add sheet, switch to **Search online**.
2. Enter title and/or artist; results list track, artist, album, duration and whether plain lyrics exist.
3. Pick a result → Overtone fetches plain lyrics and switches to the manual form, prefilled and editable. Nothing is saved until the user taps Save.

AC:
- J3.1 MUST: Manual entry remains fully usable when offline or when search fails. Offline, the Search tab shows an offline state instead of a broken request.
- J3.2 MUST: Errors (network, 404, 429 rate limit, 5xx, malformed response, timeout of 10 s) each produce a specific, human message and a Retry where appropriate. 429 honours `Retry-After`.
- J3.3 MUST: Fetched lyrics are treated as untrusted plain text: validated, length-capped, control characters stripped, never rendered as HTML.
- J3.4 MUST: Results that are instrumental or have no plain lyrics are shown as unavailable, not selectable.
- J3.5 MUST: The source (provider + provider track id) is stored with the song and shown in song details ("Lyrics from LRCLIB"). Synced (LRC) lyrics, when present, are stored untouched in `source.syncedLyrics` for future timed-lyrics features, but not displayed in v0.1.
- J3.6 MUST: A one-line notice in the Search tab states that lyrics are user-contributed third-party content provided for personal study.

### J4 — Learn a song (Learn mode)

1. Song screen opens in the song's last-used mode (default Learn).
2. Each lyric line shows the original text with pronunciation aligned above it:
   - Japanese: furigana above kanji only; romaji line beneath the original line (setting: show/hide romaji).
   - Mandarin/Cantonese: pinyin/Jyutping above each character.
   - Korean: romanisation above each word (eojeol).
   - English segments: no annotation.
3. Words are tappable. Tapping opens the Word sheet: surface, reading, romanisation, dictionary form, part of speech (if known), up to 5 senses, source dictionary, and **Correct…**.
4. Each line has a learned toggle at its leading edge. Learned lines are visually de-emphasised (and marked with a check and an accessible state, never colour alone).
5. A progress summary sits in the song header ("18 of 32 lines").

AC:
- J4.1 MUST: No horizontal scrolling at 320 CSS px width with any fixture, including long romanisations, long Latin words and URLs.
- J4.2 MUST: Annotations stay vertically aligned with their base characters/words when lines wrap.
- J4.3 MUST: Each word token is a button with an accessible name like "愛, reading あい, ai. Show meaning." Touch targets ≥ 44×44 pt effective (padding may extend beyond the glyph box).
- J4.4 MUST: Section labels and blank lines are displayed but are not learnable and do not count toward progress.
- J4.5 MUST: Tokens whose reading is unknown show the original only plus an unobtrusive "?" marker in Learn mode; their Word sheet says "No reading found" and offers Correct….
- J4.6 MUST: Tokens flagged low-confidence (e.g. ambiguous polyphones, guessed Korean lemma) show a subtle dotted underline in Learn mode, with an explanation in the Word sheet.
- J4.7 MUST: Missing dictionary entries show "No dictionary entry" — never an empty sheet or a fabricated meaning.
- J4.8 SHOULD: Long-press on a line (or line menu) offers: Mark learned/unlearned, Copy original, Copy romanised.

### J5 — Sing (Karaoke mode)

AC:
- J5.1 MUST: Shows romanised lyrics only, one lyric line per line, large type (default ≈ 28 pt, scales with text size setting), generous line spacing, section labels as small captions, blank lines preserved as stanza gaps.
- J5.2 MUST: No popups, underlines, checkboxes, or tap targets on lyrics. Scrolling is native momentum scrolling.
- J5.3 MUST: English segments are shown as written.
- J5.4 MUST: Unknown readings fall back to the original text for that token (never blank).
- J5.5 SHOULD: Screen stays readable in dark mode with no pure-white glare (uses the theme's text colour).
- J5.6 MAY: Request a Screen Wake Lock while Karaoke is visible, if the API is available, released when leaving.

### J6 — Read (Clean mode)

AC:
- J6.1 MUST: Conventional lyric layout; a segmented toggle switches Original ⇄ Romanised. The choice is remembered per song.
- J6.2 MUST: No word interactions, underlines, dictionary controls or completion indicators.
- J6.3 SHOULD: Text is selectable for copying (unlike Learn mode tokens).

### J7 — Track progress

AC:
- J7.1 MUST: Toggling a line persists immediately (optimistic UI, write within the same interaction; failure shows an error toast and reverts).
- J7.2 MUST: Progress = learned learnable lines ÷ learnable lines, computed from stored state; identical in all modes and in the Library row.
- J7.3 MUST: Repeated lines (identical normalised text, e.g. a chorus) share one learned state: marking one marks all occurrences. Progress counts occurrences (a 4× chorus weighs 4 lines). Rationale: you memorise the text once; counting occurrences matches how much of the song you can sing.
- J7.4 MUST: Correcting annotations never changes progress.
- J7.5 MUST: Editing lyrics preserves progress for every line whose normalised text is unchanged. Lines that change become unlearned. After saving an edit, a toast summarises: "Lyrics updated · 2 changed lines reset to unlearned". (Details: ARCHITECTURE.md §6.4.)
- J7.6 MUST: "Reset progress" in the song menu asks for confirmation.
- J7.7 SHOULD: Library shows a slim progress bar per song and a "Learned" badge at 100%.

### J8 — Correct an annotation

1. In Learn mode, open Word sheet → **Correct…**.
2. Editable: reading (kana for Japanese, pinyin for Mandarin with tone-mark input helper accepting numbers `ai4` → `ài`, Jyutping with tone numbers, RR for Korean), romanisation (derived automatically from the reading for Japanese, editable separately), meaning (free text, replaces or prepends to dictionary senses), segment language (e.g. mark as English / Japanese / Korean / Mandarin / Cantonese / "Don't annotate"), and word boundaries (split or merge with neighbours).
3. Choose scope: **This line** (default — applies to that word wherever this exact line text appears, including repeated choruses) or **Every line in this song** (applies to that word everywhere in the song). The data model also supports a single occurrence within a line (`occurrence`), used automatically when a word appears more than once in the same line and the user corrected only one of them.
4. Corrected tokens show a small dot marker in Learn mode; the Word sheet shows "Edited by you" and **Revert**.

AC:
- J8.1 MUST: Corrections persist across restarts, re-processing, engine upgrades and mode changes.
- J8.2 MUST: Corrections survive lyric edits for unchanged lines.
- J8.3 MUST: Karaoke and Clean modes reflect corrections immediately.
- J8.4 MUST: Input validation: pinyin syllables validated against the syllable inventory (warning, not block); Jyutping must match `[a-z]+[1-6]`; Japanese readings must be kana (romaji input auto-converted).
- J8.5 MUST: Revert restores the generated value.

### J9 — Edit and delete songs

AC:
- J9.1 MUST: Edit details (title, artist, language) and Edit lyrics (full-text editor) from the song menu. Changing language triggers re-processing; corrections tied to the old language are kept but inactive, and are restored if the language is switched back.
- J9.2 MUST: Delete asks for confirmation, then removes the song and its lines, progress and corrections. An **Undo** toast is available for 8 seconds (soft delete, purged after the toast or on next launch).
- J9.3 MUST: Swipe-to-delete in the Library is not required; delete is via the song menu or row context menu (long-press), to avoid accidental deletes.

### J10 — Find songs

AC:
- J10.1 MUST: Search box filters as you type (debounced ≤ 150 ms) across title, artist, original lyrics and romanised lyrics. Matching is case-, width- (full/half-width) and diacritic-insensitive (`ai` matches `ài`), and kana-insensitive between hiragana/katakana. Searching "saranghae" finds a Korean song containing 사랑해.
- J10.2 MUST: Language filter chips: All · Korean · Japanese · Mandarin · Cantonese (only languages present in the library are enabled; counts shown).
- J10.3 MUST: Sort: Recently opened (default) · Recently added · Title A–Z · Artist A–Z · Progress. Title sorting uses `Intl.Collator` with the song's language; romanised titles are not invented for sorting.
- J10.4 MUST: Search, filter and sort state persist across navigation and restarts.
- J10.5 MUST: Empty search results show "No songs match" with a Clear action.
- J10.6 MUST: 500 songs filter in < 50 ms on a mid-range phone class device (measured in CI on desktop with 4× CPU throttling as a proxy; real-device not claimed).

### J11 — Back up and restore

The app is account-free; JSON export/import is the only backup and transfer mechanism between browsers/devices.

AC:
- J11.1 MUST: Settings → Export creates a single `.json` file named `overtone-backup-YYYY-MM-DD.json` containing all songs, original lyrics, song settings (language, display mode, clean variant), line progress, corrections, source metadata, app settings, `format` id and `schemaVersion`. Generated annotations are not exported (they are re-derived; see ARCHITECTURE.md §7).
- J11.2 MUST: On iOS the export uses the Web Share sheet with the file (so the user can Save to Files / AirDrop) when `navigator.canShare({ files })` is true; otherwise it falls back to a download link.
- J11.3 MUST: Import validates the file (format id, schema version, structure, field types and limits) before writing anything. Invalid files are rejected with a specific reason; nothing is partially written (single transaction).
- J11.4 MUST: Import shows a preview: number of songs, how many are new vs. already present (matched by song id), and a choice: **Merge** (default; for conflicts keep the newer `updatedAt`, and union learned lines) or **Replace library** (confirm, and an automatic pre-import backup export is offered first).
- J11.5 MUST: Older backup schema versions are migrated forward on import; newer unknown versions are rejected with "This backup was made by a newer version of Overtone."
- J11.6 MUST: Round-trip guarantee: export → wipe → import yields an identical library (songs, text, progress, corrections, settings), verified by automated test.
- J11.7 MUST: Settings shows last export time. After meaningful changes (≥ 1 new song or ≥ 10 progress/correction changes) and ≥ 7 days since last export, a gentle, dismissible backup reminder appears in the Library.

### J12 — Offline and storage safety

AC:
- J12.1 MUST: After first load, the app shell, the library, all songs, Learn/Karaoke/Clean modes and progress work in airplane mode.
- J12.2 MUST: Language data for a language is downloaded on first need (with a visible progress indicator and size) and then works offline. Settings lists each pack's status and size with Download/Remove.
- J12.3 MUST: If a language pack is unavailable offline, songs still open: original text shows, with a banner "Pronunciation for Japanese needs a one-time download (≈ N MB). Connect to download." Processing resumes automatically when available.
- J12.4 MUST: The app requests persistent storage (`navigator.storage.persist()`) after the first song is saved and reports the result in Settings ("Storage: protected" / "Storage: may be cleared by iOS — keep backups").
- J12.5 MUST: If the database is found empty but a local marker indicates a library previously existed, the app shows a recovery screen explaining the data appears to have been cleared and offers Import.
- J12.6 MUST: Write failures (quota exceeded, IndexedDB unavailable, private mode) surface a clear error with an Export option where possible; the app never pretends to have saved.
- J12.7 MUST: App updates are announced ("A new version is ready · Reload") and never reload automatically while the user is editing.

### J13 — Settings

AC:
- J13.1 MUST: Theme: System (default) / Light / Dark.
- J13.2 MUST: Lyric text size: 5 steps, applied in all modes, independent of iOS Dynamic Type (which Safari does not expose to web content reliably) but respecting browser zoom.
- J13.3 MUST: Romanisation preferences:
  - Japanese: long vowels as macrons (`tōkyō`, default) or doubled (`toukyou`); show romaji line in Learn mode (default on); show furigana for kana-only words (off).
  - Korean: pronunciation-based (default) or letter-by-letter transliteration.
  - Mandarin: tone marks (default) or tone numbers; apply 一/不 tone sandhi (default off — dictionary tones, see LANGUAGE_ENGINE.md §6.4).
  - Cantonese: Jyutping with tone numbers (fixed in v0.1).
- J13.4 MUST: About & licences lists every dictionary/data source with licence and attribution, as their licences require.

## 5. Quality requirements (cross-cutting)

| Area | Requirement |
|---|---|
| Performance | Cold start to interactive Library ≤ 2 s on a 2020-era iPhone (manual check; CI proxy: Lighthouse mobile, TTI ≤ 3.5 s with 4× throttling). Opening a processed song ≤ 300 ms. Processing a 60-line song: Korean ≤ 0.5 s, Mandarin/Cantonese ≤ 1 s, Japanese ≤ 2 s after pack load (desktop CI with 4× throttle as proxy). |
| Memory | Peak JS heap while processing Japanese ≤ 150 MB on desktop WebKit proxy; worker can be terminated after idle 60 s to release dictionary memory. |
| Bundle | Initial JS (gzip) ≤ 180 KB. Language engines are lazy-loaded in a worker. |
| Accessibility | WCAG 2.2 AA: contrast, focus visible, labels, reduced motion, 200 % text without loss of function, VoiceOver navigable (manual). Language of each text run marked with `lang`. |
| Privacy | No analytics, no third-party scripts, no fonts from third-party CDNs at runtime. Network calls limited to own origin + `lrclib.net` (user-initiated). |
| Security | Strict CSP; no `innerHTML` with user or fetched content; imported JSON schema-validated. |
| Reliability | All writes transactional; schema migrations tested from every prior version. |

## 6. v0.1 completion threshold

v0.1 is complete when **all** of the following are true:

1. Every MUST acceptance criterion above is implemented and covered by a passing automated test, or — where automation is impossible (real iOS behaviour) — listed in the manual iOS checklist with status "Not yet verified on device" unless a human actually verified it.
2. All four languages produce readings and meanings offline after their pack is downloaded, measured against the linguistic fixture suites in TEST_STRATEGY.md with the accuracy thresholds there.
3. Backup round-trip, offline startup, and migration tests pass.
4. No placeholder UI: every visible control does what it says.
5. Known limitations are documented in `docs/KNOWN_LIMITATIONS.md` (created during implementation) and in the About screen where they affect users.
